# 푸시 알림 목록

이 서비스가 보내는 푸시 전부. 언제 나가는지, 무슨 문구인지, 누가 받는지,
어떤 설정으로 꺼지는지.

문구를 고칠 때는 **여기와 코드를 같이** 고쳐야 한다. 문구가 코드에 하드코딩된
것과 로케일 파일(`server/locales/*.json`)에 있는 것이 섞여 있어서, 표의
"문구 위치" 칸을 먼저 보고 어디를 고칠지 정한다.

---

## 1. 사용자에게 가는 푸시

### 자동으로 나가는 것

| 언제 | 제목 | 본문 | 문구 위치 | 끄는 설정 |
|---|---|---|---|---|
| 친구 요청을 받았을 때 | `Tichu Online` | `{닉네임}님이 친구 요청을 보냈습니다` | `locales/*.json` · `push_friend_request_body` | `push_enabled`, `push_friend_invite` |
| 문의에 답변이 달렸을 때 | `문의 답변이 도착했어요` | 제목이 있으면 `제목: {문의제목}`, 없으면 `앱에서 확인해주세요.` | `locales/*.json` · `push_inquiry_reply_*` | `push_enabled` |

친구 요청과 문의 답변은 **사용자 언어(`locale`)로 번역돼서** 나간다. ko·en·de.

### 운영자가 손으로 보내는 것

| 언제 | 제목 | 본문 | 문구 위치 | 끄는 설정 |
|---|---|---|---|---|
| 골드를 지급했을 때 (지급만, 회수는 안 보냄) | `골드가 지급되었어요` | `+{금액} 골드가 지급되었어요. 앱에서 확인해주세요.` | `admin.js` 하드코딩 | `push_enabled` |
| 무통장 입금을 승인했을 때 | `입금이 확인되었어요` | `+{금액} 골드가 지급되었어요.` | `admin.js` 하드코딩 | `push_enabled` |
| 우편을 보내면서 "푸시 같이 보내기" 를 켰을 때 | 우편 제목 그대로 | `우편함에서 확인하세요.` | `admin.js` 하드코딩 | `push_enabled` |
| 관리자 화면에서 특정 유저에게 직접 | 운영자가 입력 | 운영자가 입력 | 입력값 | `push_enabled` |
| 관리자 화면에서 전체·조건 대상 발송 | 운영자가 입력 | 운영자가 입력 | 입력값 | `push_enabled` |
| 마케팅 캠페인 | 운영자가 입력 (**`(광고)` 로 시작해야 함**) | 운영자가 입력 + 수신거부 문구 자동 추가 | 입력값 + `marketing_rules.js` | `marketing_push_enabled` (기본 **꺼짐**) |

**골드 회수(음수)에는 푸시를 보내지 않는다.** "골드가 사라졌다" 는 알림은
받는 사람을 놀라게만 한다.

---

## 2. 운영자에게 가는 푸시

관리자 계정 중 해당 항목을 켠 사람에게만 간다. 사용자에게는 안 간다.

| 언제 | 제목 | 본문 | 끄는 설정 |
|---|---|---|---|
| 신고가 들어왔을 때 | `New Report` | `{신고자} reported {대상}` | `push_admin_report` |
| 문의가 들어왔을 때 | `New Inquiry` | `Inquiry from {닉네임}` | `push_admin_inquiry` |
| 결제가 발생했을 때 | `💰 결제 발생` | `{닉네임} 님 · {상품} · {가격} · +{골드}G ({플랫폼})` | `push_admin_payment` |
| 무통장 입금 확인을 요청했을 때 | `💰 입금 확인 요청` | `{닉네임} 님 · ₩{금액} · 입금자 {이름}` | `push_admin_payment` |
| 결제가 취소·환불됐을 때 | `↩️ 결제 취소/환불` | `{닉네임} 님 · {상품} · -{골드}G 회수 ({출처})` | `push_admin_payment` |

신고·문의는 제목과 본문이 영어다. 운영자만 보는 알림이라 그대로 두고 있다.

---

## 3. 마케팅 푸시에만 걸리는 규칙

정보통신망법 §50 ④ 때문에 캠페인에는 세 가지가 더 붙는다. 판정은
`server/marketing_rules.js` 한 곳에 모여 있다.

- **제목이 `(광고)` 로 시작해야** 발송 버튼이 열린다.
- **수신거부 문구가 본문 끝에 자동으로 붙는다.**
  `* 수신거부 : 앱 설정 > 알림 > 이벤트·혜택 알림 끄기`
  운영자가 매번 적게 하지 않는 이유는, 매번 기억해야 하는 것은 언젠가 한 번
  빠지기 때문이다. 이미 들어 있으면 두 번 붙이지 않는다.
- **21~08시(KST)에는 보내지 않는다.** 관리자 화면 상단에 지금 발송 가능한
  시간인지 표시된다.

수신 동의는 **기본이 꺼짐**(`marketing_push_enabled` 기본 false)이고, 앱 첫
실행 때 물어본다. 동의자는 **2년마다 재확인**해야 하며, 기한이 지난 사람은
발송 대상에서 빠진다(관리자 화면의 "2년 재확인 대기" 숫자).

## 4. 공통 동작

**수신 설정** — `tc_users` 컬럼으로 관리한다.

| 컬럼 | 기본값 | 무엇을 막나 |
|---|---|---|
| `push_enabled` | true | 사용자 푸시 전부 |
| `push_friend_invite` | true | 친구 요청 |
| `marketing_push_enabled` | **false** | 마케팅 캠페인 |
| `push_admin_report` / `push_admin_inquiry` / `push_admin_payment` | true | 운영자 알림 (해당 항목) |

**발송 기록** — 단체 발송(우편 동봉·캠페인·일반 발송)은 `tc_push_history` 에
행을 먼저 만들고 그 id 를 페이로드에 실어 보낸다. 사용자가 푸시를 눌러
들어오면 그 id 로 열람이 집계된다. 개별 발송(친구 요청·문의 답변·골드 지급
등)은 기록하지 않는다.

**죽은 기기** — FCM 이 `unregistered` 로 거절한 토큰은 앱이 지워진 기기다.
지우지 않고 무효 표시만 해 둔다(재설치 시 같은 계정이 새 토큰을 등록한다).

**푸시를 눌렀을 때** — 페이로드의 `type`/`event` 로 갈 곳이 정해진다.

| 값 | 이동 |
|---|---|
| `friend_request` | 친구 목록 |
| `inquiry_reply` | 문의 상세 |
| `mail` | 우편함 (`mailId`) |
| `campaign` | 보상이 걸려 있으면 보상 수령 (`campaignId`) |
| `broadcast` | 앱 실행만 |

보상 수령 실패 문구는 `locales/*.json` 의 `push_reward_*` 에 있다 — 이미 받음,
기간 지남, 대상 아님, 정보 없음, 지급 실패.

---

## 고칠 때 주의할 것

- **문구가 두 군데 있다.** 친구 요청·문의 답변은 로케일 파일, 나머지는
  `admin.js`/`server.js` 하드코딩이다. 하드코딩된 것은 한국어로만 나간다 —
  해외 사용자에게도 한국어가 간다는 뜻이다. 번역이 필요해지면 로케일 파일로
  옮기는 게 맞다.
- **골드 회수에 푸시를 붙이지 말 것.** 의도적으로 빼 뒀다.
- **수신거부 문구가 가리키는 설정 경로**(설정 > 알림 > 이벤트·혜택 알림)가
  실제 화면 이름과 같아야 한다. 화면 이름을 바꾸면 이 문구도 같이 바꾼다.
