# 게임 중 강퇴

문의로 들어온 요구에서 출발한다 — **잠수 타는 사람을 기다리는 시간이 아깝다.**

## 지금은 어떻게 되어 있나

잠수 대응은 이미 있다. 문제는 대응이 없는 게 아니라 **오래 걸린다**는 것이다.

```
턴 시간 초과 → 서버가 대신 둔다 (랜덤 합법패 / 패스 / 입찰 0)
3회 초과     → 탈주 처리
                ├ 중간참여 허용 방: 봇이 자리를 이어받고 게임 계속
                └ 미허용 방: 게임 종료
```

턴 시간은 방마다 10~999초, 기본 30초. 즉 봇이 들어오기까지 **최소 90초**를
기다린다. 방장이 60초로 잡았으면 3분이다. 문의하신 분이 못 견딘 게 이 시간이다.

대기실 강퇴는 이미 있고, 게임 중에는 막혀 있다(`no_kick_in_game`).

## 무엇을 만드나

방장이 **잠수가 확인된 사람만** 즉시 봇으로 교체할 수 있게 한다. 기다림을
없애는 게 목적이지 방장에게 권력을 주는 게 목적이 아니다.

### 버튼이 보이는 조건

대상 자리에, 방장에게만, 아래 중 하나일 때만 나타난다.

- 대상의 접속이 끊겨 있다, 또는
- 대상이 이번 판에 턴을 **한 번 이상 넘겼고**, 지금 그 사람 차례로 기다리는 중이다

정상적으로 두고 있는 사람에게는 **버튼 자체가 생기지 않는다.** 이 조건이
"지고 있으니까 자른다", "강한 상대를 봇으로 바꾼다" 같은 악용을 막는 장치다.
권한을 넓게 주고 신고로 사후 처리하는 것보다, 애초에 누를 수 없게 하는 쪽을
택했다.

### 누르면 벌어지는 일

기존 탈주 처리(`handleDesertion`)와 **같은 길**을 탄다. 새 경로를 만들지
않는 이유는, 탈주에 딸린 기록·정산·자리 정리가 이미 다 붙어 있어서다.

- 봇이 자리를 이어받고 남은 사람은 판을 끝까지 친다
- 잘린 사람은 전적에 탈주 기록, 그 판 골드·경험치 0 (지금 탈주와 동일)
- 테이블에 알린다 — "○○님이 잠수로 교체되었습니다"

### 중간참여 옵션과의 관계

**강퇴는 `중간참여 허용` 옵션과 무관하게 봇이 자리를 받는다.** 방장이 직접
"봇으로 계속하겠다"고 누른 것이므로 그 뜻을 따른다. 지금 탈주는 옵션이 꺼져
있으면 게임을 끝내는데, 강퇴에까지 그 규칙을 적용하면 "기다리기 싫다"는 원래
요구를 못 푼다.

다만 **그 자리에 사람이 새로 들어오는 것은 옵션을 그대로 따른다.** 옵션이
꺼진 방이면 그 자리는 판이 끝날 때까지 봇으로 남는다. 이건 따로 만들 게
없다 — 봇 자리를 사람이 받는 경로가 이미 `allowMidGameJoin` 을 요구한다.

### 랭크전에서는 쓸 수 없다

랭크는 점수가 걸려 있어 자리 교체 자체를 지금도 막고 있다(중간참여 불가).
강퇴도 막는다. 랭크에서 잠수를 만나면 **기존대로 3회 타임아웃까지 기다린다.**

## 구현할 때 짚을 것

- **누를 때 다시 검사한다.** 버튼이 뜬 뒤 대상이 돌아와서 두기 시작했으면
  강퇴는 실패해야 한다. 화면 상태만 믿으면 "복귀한 사람이 잘리는" 일이 난다.
- **방장 자신은 못 자른다.** 방장이 잠수면 아무도 못 자르고, 기존 3회 규칙이
  그대로 적용된다.
- **관전자는 못 자른다.** 방장 권한 검사에 관전 여부를 같이 본다.
- **판이 끝났거나 정산 중이면 거부한다** (`game_end`, `deserted`).
- **한 번에 하나씩.** 연타로 여러 자리를 동시에 넘기면 정산이 꼬인다.

## 이번에 하지 않는 것

- **투표 강퇴** — 게임 중에 투표 UI 를 띄우는 부담이 크고, 2인 방에서는
  성립하지 않는다. 방장 권한으로 시작해 보고, 방장이 잠수인 경우가 실제로
  문제가 되면 그때 다시 본다.
- **턴 시간 자동 단축** — "접속이 끊긴 사람 차례면 타이머를 짧게" 는 강퇴와
  별개로 효과가 큰 개선이지만, 이번 요구(방장이 즉시 처리)와는 다른 문제다.
  따로 다룬다.
- **잠수 누적에 대한 제재** — 반복 잠수자에게 주는 불이익은 이 기능의 범위가
  아니다.

## 구현 (2026-08-21)

기획대로 만들었다. 달라진 것은 없고, 만들면서 정해진 것만 적는다.

**어디에 있나**

| | |
|---|---|
| 판정 규칙 | `server/ingame_kick.js` — `kickableReason` / `kickBlockedBy` |
| 규칙 테스트 | `server/test_ingame_kick.js` — 막는 조건 열한 개 |
| 서버 처리 | `server.js` `handleKickAfkPlayer` → `handleDesertion(..., 'kick', { forceBotHandoff: true })` |
| 화면 | `flutter_app/lib/widgets/player_profile_dialog.dart` |

**규칙을 server.js 밖에 둔 이유** — `server.js` 는 require 하는 순간 웹소켓
서버가 뜬다. 규칙이 거기 있으면 확인하려고 서버를 세워야 하고, 그러면 결국
아무도 확인하지 않는다.

**"지금 그 사람 차례인가" 를 다시 계산하지 않는다.** 그 답은 게임마다 다른
곳에 있다 — 티츄는 `currentPlayer`, 마이티 키티는 `declarer`, 교환·입찰은
아직 응답하지 않은 여러 명이다. 강퇴 쪽에서 다시 판단하면 언젠가 어긋나고,
어긋나면 멀쩡히 두고 있는 사람이 잘린다. 그래서 타이머를 거는 곳에서 받아
적는다(`turnWaitingOn`). 읽는 쪽은 강퇴뿐이라 다른 동작에 영향이 없다.

**버튼은 프로필 팝업 안에 있다.** 자리를 누르면 열리는 그 팝업을 네 게임
화면이 공유하고 있어서, 한 곳에 붙이면 티츄·스컬킹·러브레터·마이티에 전부
붙는다. 자리마다 새 버튼을 그리지 않은 것은 그 편이 화면을 안 건드리기
때문이기도 하다.

**목록은 방장에게만 내려간다.** 다른 사람 화면에 뜨면 누르지도 못할 버튼이
생기고, 무엇보다 누가 잠수로 찍혔는지 테이블 전체에 알리는 셈이 된다.

**드레인 중에는 얼린다.** 좌석 변경이 피어로 넘어갈 사본과 어긋나고,
애초에 그때는 타임아웃을 세지 않으므로 잠수 판정 자체가 성립하지 않는다.

### 아직 확인 안 한 것

기기에서 실제로 눌러 보지 않았다. 봇 승계·탈주 기록은 기존 경로를 그대로
타므로 새로 깨질 데가 적지만, **중간참여가 꺼진 방에서 강퇴 후 그 자리가
판 끝까지 봇으로 남는지**는 눈으로 봐야 한다.
